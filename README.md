# 夜间入仓作业加速测算

数仓值班工程师上传一次夜间批处理运行的时间线，选择一项作业并填入拟缩短的秒数，
页面按**本次运行实测的依赖就绪后等待时长**推算新的作业时刻，给出：

- 原本与预计的**整批完成时刻**、整批**节省秒数**；
- 决定预计完成时刻的一条**依赖链**；
- 全部作业的原/预计时刻与偏移量，以及瓶颈转移提示。

记录无效时不输出任何预测。并行分支接替原瓶颈时，收益按全批重新计算。

## 启动

```bash
docker compose up --build
```

打开 <http://localhost:8000>。换端口：`APP_PORT=8080 docker compose up --build`。

不用 Docker 时：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 使用

1. 点「载入示例」，或选择/拖入 JSON 文件，或展开「直接粘贴 JSON」。
2. 上传后会先校验记录，通过后列出作业。
3. 选择作业、填写缩短秒数（也可用 10% / 25% / 50% / 全部耗时 快捷填入）。
4. 点「测算整批提前量」查看结果。

示例文件：`samples/nightly-run.json`（15 个作业，整批完成于 46 分 40 秒）。
例如选择 `export_bi` 缩短 150 秒可直接看到整批提前 150 秒；
选择 `agg_daily` 缩短 300 秒则会看到 `agg_region` 接替成为限制、整批只提前 100 秒。

## 输入格式

```json
{
  "jobs": [
    {"id": "extract_orders", "depends_on": [],        "start": 0,   "end": 600},
    {"id": "clean_orders",   "depends_on": ["extract_orders"], "start": 660, "end": 1100}
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 作业唯一 ID，非空字符串 |
| `depends_on` | 上游作业 ID 数组；可省略。也接受 `dependencies` / `deps`，可缺省 |
| `start` / `end` | 相对批次起点（0 秒）的实际开始/结束时刻，单位秒 |

顶层也可以直接是作业数组。`start`/`end` 允许小数。

### 校验规则

任一不通过则返回错误、不产生预测：

- 作业数 2～30；
- ID 非空且不重复；
- 依赖必须指向记录中已有的作业，且不能自依赖；
- 依赖图无环（错误信息会列出具体的环）；
- `start >= 0`，`end > start`；
- 作业不得早于其任一上游作业的完成时刻；
- 缩短量 `0 < seconds <= 该作业原耗时`。

## 推算口径

对每个作业，从本次运行实测得到：

```
就绪时刻 = max(上游作业的结束时刻)，无上游则为 0
实测等待 = start − 就绪时刻            （>= 0）
耗时     = end − start
```

缩短目标作业 `T` 秒后：

- 目标作业的**开始时刻不变**（它的输入没有变化），结束时刻提前；
- 每个作业的新开始时刻 = **新的就绪时刻 + 实测等待**；
- 按拓扑序重算整批，新完成时刻 = max(所有作业的新结束时刻)；
- 节省秒数 = 原完成时刻 − 新完成时刻。

这样并行作业接替瓶颈时会被自然捕捉：例如两条并行分支原先由 A 决定批次结束，
把 A 缩短到 B 之下后，批次结束改由 B 决定，实际节省小于拟缩短的秒数。
页面会提示瓶颈转移及差额。

「决定预计时刻的依赖链」从预计的批次结束作业出发，每次沿**真正决定其就绪时刻**
的那个上游回溯到无上游的作业，形成一条真实的依赖路径。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/` | 页面 |
| `GET` | `/api/health` | 健康检查 |
| `POST` | `/api/inspect` | 校验记录并返回作业列表（`{"run": {...}}`） |
| `POST` | `/api/analyze` | 预测（`{"run": {...}, "job_id": "...", "seconds": 300}`） |

无效输入返回 `422`（JSON 语法错误为 `400`）：

```json
{"ok": false, "errors": [{"field": "jobs[3].start", "message": "…"}]}
```

有效时返回 `summary`、逐作业明细 `jobs` 和 `critical_chain`。
